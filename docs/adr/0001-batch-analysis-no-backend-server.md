# No persistent backend: batch analysis via GitHub Actions, not a hosted API server

We considered running the Python/pandas trend analysis as an always-on FastAPI service (on Render, Railway, or Fly.io) so the frontend could request suggestions on demand. We rejected this: none of those platforms have a genuinely free always-on tier as of 2026 (Railway and Fly.io dropped their free tiers; Render's free tier sleeps after inactivity, costing a cold-start delay), and the analysis doesn't need to be synchronous — it only needs to refresh a few times a day around gameweek deadlines. Instead, a GitHub Actions scheduled workflow runs the analysis and commits its output (a Snapshot, see `CONTEXT.md`) as a JSON file in the repo; the Next.js frontend on Vercel just reads the latest Snapshot. No Python service runs anywhere continuously.
